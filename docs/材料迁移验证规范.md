# 材料迁移验证规范

> 每向 MULTI-2D.2026.3 迁移一种新材料，必须按本规范执行验证，并由**新的子 agent** 独立验收。
> 本文档自包含：验收 agent 不需要任何对话上下文即可完成检查。
> 格式细节参考《MULTI-2D_材料库迁移指南.md》；现有材料见《MULTI-2D_材料库清单.md》。

---

## 1. 术语

- **IEOS**：MULTI 反演状态方程表（rho–ΔE 网格上存 P、T）
- **mgo / sgo**：多群 / 单群不透明度表
- **迁移源**：`$MULTI_LIBS/newmulti/Multi_BACK/matter++/`（或其他外部来源）
- **工具目录**：`$MULTI_ROOT/work/eos_opacity_tools/`
- **验收算例**：`cases/<材料>Check`（1D MULTI-IFE 算例）

## 2. 迁移执行步骤（迁移者填写）

| 步骤 | 操作 | 工具 |
|---|---|---|
| S1 | 复制源文件到目标位置；2D 总表放 `r94/mat_<X>-1.0/`，1D 表放 `r94/MULTI-IFE-2015/tables/` | `fix_multi_file.sh`（修 CRLF/Windows -INF） |
| S2 | 总 IEOS 拆分为电子/离子表（1D 需要） | `split_ieos_table.py <总表> <A> <e输出> <i输出> <e_id> <i_id>` |
| S3 | 逐文件格式验证 | `check_multi_file.py` |
| S4 | 拆分自洽性抽查（Pe+Pi vs P_tot，与官方 Be 表偏差同量级即合格） | 自写脚本（可仿照指南 §7.4） |
| S5 | 2D 材料函数：`r94/m2d-core-9.1/Material.r` 添加 `Material<X>()`，重编译模块 | `cd r94/m2d-core-9.1 && x.2.library` |
| S6 | 建立 1D 验收算例 `validation_cases/<X>/<X>Check/`（模板见 §3；输出频率须满足 E 节要求） | 克隆 `validation_cases/Ti/TiCheck` |
| S7 | 运行算例 | `cd validation_cases/<X>Check && ./RUN` |
| S7b | 生成可视化（密度热图 + 中间时刻剖面，存入算例目录） | `plot_1d_validation.py` |
| S8 | **提交新子 agent 验收**（提示词模板见 §5） | — |
| S9 | 更新《MULTI-2D_材料库清单.md》，状态标"待人工确认"；**用户人工确认（F 节）后标"完全迁移 ✅"** | — |

id 分配约定：电子表 `Z×10⁷+304`，离子表 `Z×10⁷+305`（Z=原子序数）；不透明度/电离度表沿用源文件 id。

## 3. 验收算例设计模板

算例名：`validation_cases/<X>/<X>Check`（**独立目录，与 `cases/` 下的官方算例分离；算例与全部产物永久保留**）。文件：`data.in`、`RUN`、`FILELIST`、`CLEAR`（后三者克隆自 `validation_cases/Ti/TiCheck`）。

**目录归组约定（2026-08-13 起）**：同一材料的所有校验产物归到 `validation_cases/<材料>/` 一个文件夹下：
- `<X>Check/` —— 迁移验收算例（含 output、fort.10/11、两张 PNG）
- `hugoniot_T<强度>/` —— Hugoniot 校验算例（内含 `hugoniot_points/` 逐点溯源图）
- `hugoniot_summary/` —— Hugoniot 汇总（CSV + 对比图）

物理设计（原则：简单、快速、同时激发 EOS+不透明度+电离三张表）：

- 几何：平面（`igeo=1`），单一材料平板，厚度 ~2 μm，固体密度，20 单元
- 驱动：右侧恒定辐射温度浴 `betar=1, itype=2, trad=100 (eV), tau=1e-9`
- 时长：`texit=1.2e-9`，`dtmax=dtinit=1e-11`（约 121 步，秒级完成）
- 开关：`iradia=1, ihydro=1, inegpre=0, zmin=0.1`；不含激光块
- 材料块：挂新迁移的 eeos/ieos/z/planck/ross 五张表，`eps_id=-1`

## 4. 验收标准（子 agent 逐条核对）

### A. 格式合规（必过）

```bash
M=$MULTI_ROOT
python3 $M/work/eos_opacity_tools/check_multi_file.py <每个迁移文件>
```
- A1 全部输出 `✓`，退出码 0
- A2 IEOS 表的 NR/NE 与迁移记录一致；mgo 子表数=群数；sgo type 字符串正确

### B. 算例运行（必过）

在 `cases/<X>Check/output` 中：
- B1 含 `normal program termination`
- B2 能量相对误差 `error` 行：绝对值 < 1e-4（2026-08-13 由 1e-6 放宽；
  原阈值过严，无法容纳气体/相变等强非线性材料；能量守恒仍受 B5 约束）
- B3 表加载摘要中：`eeos_file`、`ieos_file` 指向新表且 NR/NE 正确；`planck`/`ross` 的 `ng`（群数）与源表一致；Z 表（若挂）NR/NT 正确
- B4 实际到达 `texit`（步进日志最后一行 time = texit）
- B5 能量收支合理：`radinr > 0`（辐射进入）、`derad > 0`（有沉积）、电子/离子能量上升、无 NaN/异常巨大值
- B6 无 `ERROR`、`STOP`、`premature eof` 等字样

### C. 物理合理性（必过）

- C1 `check_multi_file.py` 输出的网格范围覆盖算例实际状态（ρ 含固体密度；T 覆盖 0.03 eV–100 eV 以上）
- C2 拆分表自洽性记录（S4）的偏差与官方 Be 表同量级（~20% 内为正常，源于方法与粗网格）
- C3 2D 材料函数存在于 `r94/m2d-core-9.1/Material.r` 且 `Material.c` 已重新生成（`grep -c "Material<X>" Material.c` ≥ 1 且文件新于 Material.r 或同日）

### D. 文档登记（必过）

- D1 《MULTI-2D_材料库清单.md》已登记新材料及全部文件
- D2 迁移来源、日期、验收算例名已记录

### E. 可视化（必过）——2026-08-10 新增

验收算例目录固定为 `validation_cases/<X>/<X>Check/`（**算例与结果永久保留，禁止删除**）。
算例输出频率须满足热图分辨率：`ns_bout=1`（或 `dt_bout ≤ texit/100`）。
运行结束后生成可视化（工具：`work/eos_opacity_tools/plot_1d_validation.py`）：

```bash
python3 $MULTI/work/eos_opacity_tools/plot_1d_validation.py validation_cases/<X>Check
```

产物（存于算例目录内）：
- `density_heatmap.png` —— 密度热图 ρ(x,t)
- `profiles_mid.png` —— 中间时刻（最接近 texit/2 的记录）密度、温度(Te/Ti)、压强(Ptot/Pe) 剖面三联图

验收条目：
- E1 两个 PNG 文件存在且非空；解析记录数 ≥ 50
- E2 热图显示密度场随时间连续演化、无断带/无 NaN 空洞
- E3 剖面图曲线光滑、物理量纲合理（ρ>0；T 在表覆盖范围内；P 无异常振荡）
- E4 中间时刻记录的实际时间在 texit 的 45%–55% 区间

> 说明：1D 程序（m150304.f95）写出的 fort.10 为 **ASCII** 格式，与
> `$MULTI_APP/MULTI1Dvisual2.2`（徐博的 GUI 工具）期望的**二进制**
> fort.10（Windows Multi1D 格式）不兼容；可视化脚本解析逻辑参照该工具的
> `legacy/scanFile.py` 变量命名（R/PT/TE/PE/ZI/XC/X/TR…），如需 GUI 交互查看
> 可另行转换二进制格式。

### F. 人工确认（最终闸门）

- F1 验收 agent 全部 PASS 后，由用户人工查看 `validation_cases/<X>/<X>Check/` 中的
  `output`、`density_heatmap.png`、`profiles_mid.png`
- F2 **用户明确确认后**，才能在《MULTI-2D_材料库清单.md》验收记录中标记"完全迁移 ✅"；
  在此之前状态为"机器验收通过，待人工确认"

### 历史问题与修复记录

1. **Ne 不透明度退化子表**（2026-08-10）：Thermos 源文件第 50 子表 f1==f2=1200 eV，触发 1D `load_table_multi` 的结束误判，后 28 群被静默丢弃。修复：删除退化子表（77 群），`batch_migrate.py` 已内置 `drop_degenerate_groups()` 自动处理。
2. **Kr 算例物理崩坏**（2026-08-10）：固体密度（2.5 g/cc）算例辐射坍缩使 ρ 冲出表范围（1890 vs 10 g/cc）。修复：算例改用气体密度（3.749e-3 g/cc），误差 1e-13。
3. **压强单位 bug**（2026-08-10）：`batch_migrate.py` 的 hyades→MPa 换算误用 ÷1e11（正确为 ×1e-7），致全部 hyades 源转换表压强小 1e4 倍。首轮验收靠能量守恒未能发现，由 Kr 剖面 Pe≈0 异常暴露。修复后 20 种材料重迁移重跑，子 agent 复验时与源表直接数值对照（≤3%）确认。**教训：验收必须包含与源表的物理量绝对值对照，不能只看守恒量。**
