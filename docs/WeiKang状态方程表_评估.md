# WeiKang 状态方程表 → MULTI 转换评估

> 源目录：`$MULTI_LIBS/newmulti/weikang状态方程表_汇总/`（北大五本博士论文提取的 DFT/FPMD 级 EOS 数据）
> 评估日期：2026-08-11。转换工具链沿用 `work/eos_opacity_tools/` + EOS-tools。

## 一、源格式理解

全部为**空格对齐的 ASCII 文本**：首行列头，`#` 注释（头部注明出处/页码/原书排版问题处理）。每行一个 (ρ,T) 状态点，给出 P 和/或 E。**16 个 EOS 文件 + 3 个非 EOS 对比表**。

与 MULTI IEOS 的差异：这些是 (ρ,T) 直表（总 EOS，电子+离子混合），需经 RT→RE 反演转换；单位各异（Mbar/KBar/GPa；eV每原子/Ry/Ha；K/eV）；能量有各自的零点偏移 E0（IEOS 的 E0(ρ) 冷能基准天然兼容，无碍）。

### C. 不建议转换——5 个

- 张肖涵_表4.2/4.3_雨贡纽插值 ×2：计算点+雨贡纽点混合的非网格数据（用途是雨贡纽插值拟合），转成规则 EOS 网格会引入额外插值误差；如需可用其"计算点"部分
- 其他表格/ ×3（Al 方法对比、D 泛函对比、KCl 压强成分）：单点对比表，非 EOS 网格，不可转

## 三、已有半成品的状态（multi格式/）

`Fe_铁_total.multi`、`CH2_聚乙烯_total.multi` 两个文件**数据体已是 IEOS 布局**（15 字符定宽、4 值/行：ρ 网格 + ΔE 网格(128) + E0 + P + T），但：

1. **头部不合规**：`2 7.85 8 128` 空格分隔仅 13 字符——MULTI 严格要求 60 字符（4×15 字段）。已用 `check_multi_file.py` 实测：报 `头行长度=13 != 60` ✗
2. **CRLF 行尾**：需 dos2unix
3. 修复方法（两选一）：
   - 直接重写头：把 `2 7.85 8 128` 换成 `%15.8e`×4 的 60 字符头（id 可给 26000304 类），去 CR
   - 或用 EOS-tools 读入后重新 save（其 reader 兼容这种头）

## 四、转换路线（沿用已验证流水线）

```
.txt (ρ,T,P,E) → 按块组装规则网格 → EOSDataset(electron=总量, ion=理想气体)
   → EOS-tools multi writer (自适应 ΔE) → 总 IEOS (r94/mat_X-1.0/X_eos)
   → split_ieos_table.py → 1D 电子/离子表
   → check_multi_file.py 验证 → XCheck 算例跑通 → 子 agent 验收
```

单位映射要点：Mbar→MPa ×1e5；KBar→MPa ×100；GPa→MPa ×1e3；eV/原子→J/g ×(1.602e-19/(A·1.6605e-24))/1000；Ry×13.6057 eV；Ha×27.2114 eV；T(K)÷11604.519→eV。化合物 E 按式量除每式单位原子数。

## 五、建议

1. **优先转换（新增材料）**：**LiF（A.1+A.2 两表拼宽区）、BN、C9H10** —— 这三种是库里没有的
2. **次优（高质量替代/对比）**：刘兴 H、C、C8H8、CH2、高畅 Si(PBE)
3. **顺带修复**：multi格式/ 的 Fe、CH2 两个半成品（重写头+去 CR 即可）
4. 转换后按《材料迁移验证规范》走 XCheck + 子 agent 验收流程
5. LiF/BN 无不透明度数据——迁移后属"仅 EOS"档（2D 可用；1D 需另找不透明度或用借用策略，如 LiF 可评估借 Li 表/更合适的卤化物表）
